看电视 1.3.0
================

安装与开启 AI
------------
安装“看电视-v1.3.0.apk”，与上一版使用相同签名，可覆盖升级。
最低 Android 5.0，支持电视、盒子和安卓设备。包名 com.kandianshi.tv。
内置央视、卫视和地方台列表共 442 个频道，启动即可尝试播放。
上/下换台，确认键打开频道列表，右键或菜单键打开设置。

1. 电视与手机连接同一个可信家庭 Wi-Fi。
2. 电视进入“设置 → AI 维护 / 手机扫码配置”。
3. 点击“手机扫码配置 API / Key / 来源”，用手机扫描二维码。
4. 开启“启用 AI”，填入自己的 API Key。DeepSeek 地址和模型已预填。
5. 点击“测试 API 连接”，成功后点击“保存到电视并结束配对”。
6. 返回电视，可点击“立即检测与更新”；之后按设定间隔自动维护。

DeepSeek 默认地址：https://api.deepseek.com
默认模型：deepseek-flash
也支持使用 Chat Completions 格式的其他 HTTPS API。
安装包和源码均未内置 API Key，需要在自己的电视上输入后才能调用 AI。
再次配对时留空 Key 会保留原密钥；勾选“清除”可删除。

APP 内部维护
------------
播放器、订阅解析、网页来源发现、线路检测、缓存和任务调度都在 APP 内。
模型推理通过所配置的 API 完成，需要联网；无需另外部署维护服务器。
自动维护可选每 6、12、24 小时。AI 来源搜索筛选约每天一次。
来源发现和连接测试每日最多 3 次；图片巡检有独立每日 10 / 50 / 200 次限额，费用由服务商计算。
任务受电视的待机、省电和联网状态影响，无法保证精确时刻运行。
关机时不执行；重新打开 APP 后会检查是否需要补做。

内置订阅来源包括 iptv-org/iptv、vbskycn/iptv 和 YueChan/Live。
扩展来源不限 GitHub：手机网页可添加公开 M3U/TXT 订阅或公开网页，每行一个，最多 20 个。
程序提取静态网页中的公开订阅/媒体链接，不执行网页脚本、不处理登录和加密付费直播。
AI 只从已有搜索结果中挑选候选，不自行编造播放地址。
AI 新来源经过解析和媒体样本检测后才会加入；失败时继续保留已有列表与缓存。

每轮轮换检测少量线路，并结合播放过程记录的成功、错误和超时结果调整优先级。
播放器每个频道保留最多 8 条候选线路，失败后自动尝试下一条。
“媒体可达”代表拿到了清单和少量媒体数据，不能保证电视端解码成功。

广告及错误画面
--------------
电视“AI 源维护”页面可屏蔽当前线路，返回播放器后生效。
也可在手机配置页填写完整线路地址或域名；删除对应屏蔽项后保存即可恢复。
本版可在电视维护页进行台标与纯广告画面巡检。正常电视台插播广告保留，疑似无台标纯广告经确认后移除。

扫码网页与密钥
--------------
网页默认关闭，仅在电视主动打开配对页面后临时开启。
只绑定电视的家庭局域网 IPv4 地址，限制同一子网，拒绝跨站及显式代理转发请求。
二维码包含随机配对令牌，有效期 10 分钟；保存成功、离开配对页面或手动关闭后失效。
Key 使用 Android 系统密钥库保护后保存在电视内部，不在配置读取接口回显，也不写入维护日志。
AI 服务请求使用 HTTPS，公开网页搜索摘要会发给配置的模型服务商。
手机到电视的临时配置网页使用 HTTP，应在可信家庭 Wi-Fi 内使用。
不要设置路由器公网端口转发；应用无法控制路由器、VPN 或同网段其他设备。
部分路由器启用“无线隔离”后手机无法访问电视，需要连接允许设备互访的家庭网络。

验证范围
--------
前版完成局域网配置及真实 DeepSeek 文本 API 测试；本版新增图片巡检的源码与单元测试，尚未完成电视实机与视觉 API 联调。
真实测试使用用户授权的 Key，只用于测试，未存入安装包和源码。
浏览器预览工具无响应，未完成网页视觉验收；当前没有电视实机或安卓模拟器进行安装、扫码和解码验证。
在线源受地区、运营商和时间影响，不能保证所有 442 个频道均可播放。
上一版源检测结果保留在 stream-checks.json / direct-checks.json，属于 2026-10-09 的网络样本，不能视作长期有效。
上游项目信息及原作者说明保留在源码包 notices 目录。

文件存放
--------
源码、缓存和交付物实际存放于 D:\CodexWork\kan-dianshi。
Codex 输出目录是指向 D 盘的目录联接，未在 C 盘复制 APK 或大型文件。


看电视 1.3.0：黑屏与无效线路清理
==============================

覆盖安装“看电视-v1.3.0.apk”，包名和签名保持不变，保留原 API 配置。
本次清理功能不需要 API Key，不调用 AI，也不消耗 DeepSeek 额度。

一键检测
--------
打开设置 → AI 维护 / 手机扫码配置 → 检测并移除无效线路（全列表）。
可返回播放器继续看电视；维护页下方会显示轮次、进度和移除数量。
检测检查 HTTP 请求、HLS 主清单与媒体清单，以及真实媒体分片数据。
不会把 Ping 通、网页返回 200 或只有一份有效清单当作播放成功。

第一轮检查当前列表的候选线路，后两轮只复核失败线路。
复核轮次之间等待 45 秒；最多 3 轮，单次最多 2000 条候选线路。
失败计数至少间隔 30 秒，连续 3 次失败后才从播放列表移除。
检测可能持续较长时间，取决于线路数量、网络和系统调度。
可点“停止全列表检测”；再次点击检测会继续未完成进度。
如果检查过程中整批失败，而且无法确认其他媒体线路可用，会暂停清理并保留列表。
如果电视网络不可用，播放失败不会计入删除。

删除与恢复
----------
处理的是单条播放线路。有备用线路的频道继续保留；所有线路被移除后，频道才隐藏。
移除记录持久保存在电视内部，订阅更新不会直接重新启用同一个已移除 URL。
打开“查看 / 恢复已移除线路”，可查看原因，点击恢复一条或选择“恢复全部”。
恢复会重置该线路的失败计数，返回播放器后生效。
因传输请求失败被移除的线路，之后两次间隔媒体检测成功也会自动重新加入。
因无视频首帧或解码失败被移除的线路，不会因为 HTTP 又能下载就自动恢复。
手动报告黑屏移除的线路需要手动恢复。
原有广告线路屏蔽列表是独立功能，仍在手机配置页删除对应屏蔽项后恢复。

播放时处理黑屏
--------------
打开一条线路后，20 秒没有显示视频首帧，自动切换备用线路。
已显示画面后，缓冲超过 15 秒、播放器报错或直播提前结束，也会尝试备用线路。
只有显示过视频首帧并持续播放 3 秒，才记录为一次实播成功。
只有声音没有视频首帧，不会被当作成功。
短时间重复回调只算一次失败；旧频道的迟到画面或错误不会作用于新频道。
清理刷新列表时会尽量保留正在正常播放的同一条线路，避免反复重启视频。

如果画面已经解码出来，但内容一直是黑画面，当前程序不能可靠识别画面语义。
可在维护页点击“当前黑屏，移除此线路”，返回后改用备用线路；需要时可恢复。
加密 HLS 和无法确认格式的媒体保留给电视实播验证，不直接按失效删除。

说明
----
“移除”指从本机播放列表排除，保留可恢复记录，不修改上游 GitHub 或网站内容。
内置列表仍是 442 个初始频道；实际显示数量随订阅、检测和移除结果变化。
网络探测不能替代电视解码验证，无法保证所有频道均能播放。
当前没有电视实机或安卓模拟器进行安装与真实视频输出验收。


看电视 1.3.0：台标与纯广告画面巡检
================================

DeepSeek 官方图片接口：deepseek-flash。
说明：https://api-docs.deepseek.com/guides/vision/
官方接口可接收图片；具体电视台台标识别效果仍需实机验证。

使用
----
1. 覆盖安装“看电视-v1.3.0.apk”，原 API 配置保留。
2. 设置 → AI 维护 / 手机扫码配置，启用 AI，DeepSeek 模型填写 deepseek-flash。
3. 打开“AI 画面巡检：识别无台标纯广告”。
4. 可先点“仅识别刚才观看的线路”；或“开始 / 继续全列表巡检”。
5. 巡检页会静音播放候选线路；等到真实首帧后，稳定 3 秒再开始取样。
6. 每条取 3 张节目画面，间隔 10 秒，三张合成一次图片请求。
7. 在“查看疑似纯广告，逐条确认”查看判断依据，确认后移除。
8. 误移除时，在维护页“查看 / 恢复已移除线路”恢复。

判定
----
任意一张图出现电视台台标，就保留，包括央视和地方台正常插播广告。
三张图均无台标、均呈明确广告特征，且每张模型信心至少 0.93，才进入疑似列表。
产品商标、购物电话、促销二维码和普通水印不视为电视台台标。
没有台标本身不算广告；正常节目、新闻、电影、赛事和片头不能仅据此移除。
无台标但不是明确广告、看不清台标、模型无法判断，都保留。
黑屏、没有可抓取的视频、受保护的视频、全平色截图及三张完全相同的截图不送模型，不因截图失败移除。
短期三次取样不能证明某线路全天均为广告，因此本版不自动删除疑似线路。
选择“本次保留”只结束本次待确认，后续新巡检仍可重新识别。
移除只影响该条 URL，本机保留恢复记录；有其他线路的频道继续保留。

范围与进度
----------
全列表先逐频道检查首选，再轮换备用；按 URL 去重，最多 2000 条。
进入巡检前释放正常播放器的解码资源，返回时重新准备原频道。
已移除、手动屏蔽的线路跳过。
完成的每条立即持久化结果和进度；暂停、退出、重开后点继续即可。
识别单条线路使用独立进度，不覆盖全列表进度。
返回播放器会暂停巡检；需要保持巡检页在前台、电视开机联网。
本版未在后台静默解码全部频道，也不在用户观看时另起播放器抢占解码器。
本轮完整结束后再次点击开始，会按当时列表启动新一轮。

费用与隐私
----------
会把节目画面发送到你配置的 AI API，图片与文字按服务商规则计费。
不会发送整个电视屏幕，只读取巡检播放器的视频 TextureView，不读取密钥配置页。
截图压缩为 JPEG，最大 960 像素宽，保留整个画面和四角；使用原图细节模式识别小台标。
截图只在内存处理，不保存相册，也不上传到额外的文件托管服务器。
默认每日最多 10 次图片请求；可在巡检页改为 50 / 200 次。
每条线路三张图对应一次调用；HTTP/API 失败也扣本地次数。
到上限暂停并保留未完成进度，不自动循环重试，不额外发连接测试。
计数按 UTC 日期重置（北京时间次日 08:00）；明日打开继续，或主动调整额度。
图片额度与原有来源发现/连接测试的每日 3 次分开。
离开页面会取消后续步骤；已经发出的单次请求仍可能完成并产生费用。
Key 继续由 Android Keystore 保护；本安装包和源码未内置用户 Key。

验证与限制
----------
已有无效线路清理、断线换源和二维码配置继续保留。
新增单元测试验证台标优先、无台标非广告保留、三帧独立证据、低置信度保留、限额、进度和恢复。
官方文档确认 API 图片输入能力；本版尚未完成电视实机截图到模型的完整连通和识别准确率验收。
本版额外进行 1 次三张合成图片 API 实测（1180 token），识别到 CCTV1 文字台标并保留。未用真实电视截图。
模型可能漏认或错认台标；判断依据只反映当时取样，请逐条确认。
