# CCTV1 / CCTV6 加载修复（1.14.2，2026-11-09）

原先内置的部分境外线路超时或返回非媒体内容，每条20秒和节目单刷新可能让用户长时间只看到加载。此次按用户指定频道直接测试实际节目单，没有用央视新闻或测试URL替代这两个频道。

引导节目单补充7条公开国内H.264线路，来自 best-fan/iptv-sources 的 cn_cctv_status.m3u8 和 jiandantv/IPTV2026 的 live_lite.m3u。只访问项目明确公布的地址，没有枚举IP或绕过鉴权。无代理直连检查了媒体清单、视频分片、PAT/PMT以及清单推进；排除了一个名为CCTV6但只有AAC音轨的地址。引导线路用于初始排序，本机健康记录和用户屏蔽仍优先；相关订阅使用现有6小时轮询和候选验证，不整批信任新地址。

单线路15秒首帧上限、等待前台解码器3秒、同一频道首轮总计45秒。列表重建不会刷新此期限，失败后同名模型不会重开播放；明确点击和重新进入播放器可重试。长时间正常播放后失效会获得新的恢复窗口。解码器资源忙不记录为节目源网络故障。计时与本轮失败集合位于内存，继续沿用已有批量持久化。

新增纯Java MPEG Layer II音频回退，原生可处理的音轨仍优先使用系统解码。无原生.so，不增加ABI或16KB页依赖；JLayer许可证、原始JAR和对应源码一并交付。每帧输入和PCM输出均有上限，队列有界，不进行音频落盘。

TS探测只在完整PAT和所有相应PMT均明确为已知音轨时拒绝；缺表、片段表、未知私有轨道保留未知，避免误删。

验证：348项单元测试、Lint零错误、构建、原证书签名与16KB对齐通过。CctvPlaybackInstrumentation对实际签名release执行真实菜单点击CCTV1、CCTV6、再回CCTV1，不注入替代频道或指定外部测试URL。每次出帧后持续12秒，检查渲染帧数增长、当前实际路线、音轨、连续PCM输出及isPlaying，并保存屏幕截图。PlaybackInstrumentation另验证HTTP受控视频可见像素、手动换台、失败后换台、失去列表观察者的备用线路、同台重试、无响应源超时及同名频道刷新不能重启失败加载。

边界：测试环境API25 x86安卓模拟器，未连接小米15Pro/Android16或电视真机；来源会随地区和时间变化，本次成功不承诺所有来源永久可播。此次没有调用付费模型。
