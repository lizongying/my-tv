# 重温经典原生解析

依据用户于 2026-11-08 提供的 cwjd.php（3285 字节）和 TXT（36 字节）研究协议，并用 Kotlin 独立实现。未运行或嵌入 PHP，没有搭建对外服务。原附件保持原位。

原脚本从 `?id=` 读取 resId，未提供参数时默认 30167，可为不同的已知 ID 分别请求地址：先向 saleservice.5gtv.com.cn 的权限接口提交节目 ID，再向 live-dispatcher.5gtv.com.cn 请求临时地址，原 PHP 用 HTTP 跳转交给播放器。TXT 只是一条指向 PHP 网站的频道记录，不能提供频道爬取能力。

APP 固定处理这一频道，保留证书验证，不使用 PHP 关闭 TLS 验证的做法。请求仅向固定的两个 HTTPS API 发送协议头；服务拒绝时直接失败并冷却，不尝试其他 ID 或权限回退。需要设备时间正确。接口协议可能改变。

内部稳定 URI 用于节目单、健康记录和广告记忆，由程序的 HTTP 适配器解析，不是供第三方播放器直接使用的公开媒体链接。临时地址缓存只在内存，最长 5 分钟；单次错误主动刷新受播放器的一次重试及解析器 15 秒失败冷却限制。原始清单 URI 别名保留最多 64 个，保留首个别名以支持长时间观看；普通分片及其他频道不触发鉴权，也不被此解析任务的锁阻塞。主播放、手动与后台截图巡检使用相同适配器。

候选播出由既有 LiveStreamVerifier 把关，不把“权限接口返回成功”当成节目可播。后台维护不反复把短期 URL 写入存储。

独立接口检查：2026-11-08，启用证书校验，两层 API 均返回成功并给出地址。该检查尚不能证明媒体清单持续推进、实际画面正常或电视实机兼容。最终验证范围见本版 validation JSON。

## 再次核对：自动更新与发现的边界

用户强调的算法更新能力是准确的：generateSign 为每次请求生成新签名，资源权限与流调度接口返回该 ID 当前的播放地址；超过缓存期限，下次请求会重新获取。原 PHP 支持输入其他 ID，不是写死单频道。1.13.0 限定 30167 是本项目当时的集成与验证范围，不是原 PHP 的能力限制。

签名函数生成的是请求签名，不是直播 URL，也不生成频道 ID。原文件没有读取频道目录、搜索、分页、遍历频道或寻找新 ID 的逻辑。PHP 也没有定时后台任务；它由播放器请求触发，缓存超过 600 秒后才更新。

要实现自动发现和更新多个节目，需要把两个模块接起来：公开目录/订阅提供频道名称和资源 ID；此协议适配器根据已发现的 ID 获取、更新地址，并继续进行直播验证。单有签名算法无法知道平台有哪些频道，也不能证明其他 ID 都可播放。

本轮只读检查了平台公开首页，以及 GitHub 中包含已知接口名/主机的公开实现，未找到可确认的自动频道目录接口。此结论只限本次检查，不能据此断言平台没有相关接口。没有尝试猜测或枚举资源编号，也没有扩大已验证频道的范围。
