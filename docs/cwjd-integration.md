# 重温经典原生解析

依据用户于 2026-11-08 提供的 cwjd.php（3285 字节）和 TXT（36 字节）研究协议，并用 Kotlin 独立实现。未运行或嵌入 PHP，没有搭建对外服务。原附件保持原位。

原脚本只处理默认 resId=30167：先向 saleservice.5gtv.com.cn 的权限接口提交节目 ID，再向 live-dispatcher.5gtv.com.cn 请求临时地址，原 PHP 用 HTTP 跳转交给播放器。TXT 只是一条指向 PHP 网站的频道记录，不能提供频道爬取能力。

APP 固定处理这一频道，保留证书验证，不使用 PHP 关闭 TLS 验证的做法。请求仅向固定的两个 HTTPS API 发送协议头；服务拒绝时直接失败并冷却，不尝试其他 ID 或权限回退。需要设备时间正确。接口协议可能改变。

内部稳定 URI 用于节目单、健康记录和广告记忆，由程序的 HTTP 适配器解析，不是供第三方播放器直接使用的公开媒体链接。临时地址缓存只在内存，最长 5 分钟；单次错误主动刷新受播放器的一次重试及解析器 15 秒失败冷却限制。原始清单 URI 别名保留最多 64 个，保留首个别名以支持长时间观看；普通分片及其他频道不触发鉴权，也不被此解析任务的锁阻塞。主播放、手动与后台截图巡检使用相同适配器。

候选播出由既有 LiveStreamVerifier 把关，不把“权限接口返回成功”当成节目可播。后台维护不反复把短期 URL 写入存储。

独立接口检查：2026-11-08，启用证书校验，两层 API 均返回成功并给出地址。该检查尚不能证明媒体清单持续推进、实际画面正常或电视实机兼容。最终验证范围见本版 validation JSON。
