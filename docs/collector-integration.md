# 采集工具与安卓集成

参考项目：
- https://github.com/testtff/TV （检查时最后推送 2025-04-15；MIT）
- https://github.com/Guovin/iptv-api （检查时最后推送 2026-10-14；AGPL-3.0）

本版独立实现公开订阅数据格式兼容，未复制、修改或分发上述项目的 Python 源码与依赖，也未把第三方生成节目单打包为默认频道。上游声明分别适用于各自代码；节目内容的权利属于原提供者。

## 已接入

默认维护入口读取 testtff/TV 的 config/config.ini 和 Guovin/iptv-api 的 config/subscribe.txt。旧 INI 只读取 Settings 中启用的 subscribe_urls；新列表与无标签 URL 索引按行读取。注释、命令、非 HTTP、内网与携带账号的地址不会加入。纯列表中的 UA 标注只提取 URL，不转发请求头。白名单分区不豁免逐条验证。

公开 Git 仓库的目录含有采集工具结构时，只读取订阅配置和一份优先的 output/result.m3u（否则 result.txt），避免枚举 RTP、模板、别名和黑名单。直接订阅配置不再自动扩展到整个仓库。用户自行添加仓库时仍可读取其历史结果，但每条地址均须验证后显示。

某些已知 GitHub 镜像外链还原为公开原地址；查询参数保留用于区分频道。上游当前 subscribe.txt 为空时保持为空，不启用文档中的示例。默认入口仍可能过期，遵循既有失败冷却；本版不承诺新增可播频道数量。

发现的子订阅走同一个持久队列，再经 SourceTools、CandidateAdmission 和 LiveStreamVerifier。索引解析不执行网络请求，实际下载复用 HttpFetch 的 DNS、重定向、响应大小与超时限制。每份索引最多 24 个去重入口、最多处理 2000 行与 512 KiB 文本；现有队列 128 页、候选 1024 条、维护请求和时间上限不变。

## 保留的运行机制

常驻服务在播放时约每 5 分钟轮转轻量任务，缓冲时让行；退出桌面后继续空闲维护，批次间隔约 15 分钟。普通状态在内存合并保存。画面广告巡检仍为空闲任务，沿用确认、记忆与恢复功能。本版没有新增付费模型调用，也没有改动广告判定算法。

## 尚未移植的上游能力

Python/Selenium/FFmpeg 引擎、FOFA/酒店/组播扫描、上游桌面 GUI、推流转码和回看配置未包含。没有增加 IPTV 私网、认证或付费权限绕过。HTTP/媒体验证不等于设备能成功解码；频道是否可播仍须以用户所在网络和设备出画面为准。
