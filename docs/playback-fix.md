# 播放与换台修复（1.14.1）

症状：首个地址播放失败后，点击其他台仍然黑屏；节目单刷新后可能不再切备用线路。

原因：MainFragment 点击回调错误地以当前地址是否为空作为发起播放的条件；自动刷新重建模型并移除观察者，PlayerFragment 的失败切换又只通知旧模型。两者叠加，可能让所有后续点击都无法改变当前播放请求。

修复：每次明确点击都提交所选频道，播放器自行保留健康同台播放；明确点击重置本轮失败集合。刷新后将新模型关联到播放器，保持健康地址不重新 prepare。备用线路由播放器直接调用 play，独立于列表 LiveData。加载和失败状态在屏幕显示；日志仅包含请求代号及错误名称，不记录地址或密钥。

验证：330 项单元测试、Lint 0 错误及原签名检查通过。PlaybackInstrumentation 使用原创本地视频经 HTTP 服务交给真实 PlayerFragment，通过实际点击回调验证换台，移除频道观察者后验证备用线路；验证同台重试。相同测试包用原证书签名，对实际 release APK 执行；浙江卫视和 央视新闻（CCTV13） 的 HLS 样本均实际收到渲染首帧并继续播放。截图和详细记录在交付验证 JSON 中关联。

边界：API25 x86 模拟器验证，未连接 Xiaomi15Pro/Android16 或电视真机。协议抽查存在超时和 HTTP200 非直播内容；来源随网络地区和时间变化，修复不等同于每条频道地址始终有效。未调用付费模型。另有CCTV1境外IP样本在Android实际直连20秒未出帧，桌面禁用代理直连复查同样超时，已保留失败结果；此地址没有计入成功样本。
